# Phase 5：长对话记忆与摘要压缩

## 记忆分层

- 最近消息窗口：每次调用只加载最近 `rag.agent.recent-message-limit` 条消息，默认 12 条。
- 结构化摘要：达到 `summary-trigger-count` 后，将窗口外消息压缩为服务名、版本、风险、发现、用户决策、已完成检查和待办事项。
- 评审状态：结构化内容同步保存到 `ReleaseReview`，并通过 Session 的摘要游标标记已压缩到哪条消息。

## 实现过程

`ConversationMemoryService` 在构建模型上下文时先检查消息数。只取游标之后、最近窗口之前的消息，结合已有 JSON 状态调用模型摘要；摘要解析成功才推进游标，失败则记录警告并继续用最近消息，避免摘要异常阻断评审。

使用 `summaryThroughMessageId` 而不是每轮都摘要全部历史，可避免重复压缩和摘要成本随会话长度线性增长。Flyway V3 为游标增加字段。

## 上下文组成

```text
固定安全规则 + 结构化评审状态 + 最近 12 条对话消息 + 本轮工具定义
```

## 当前边界

摘要目前在 Agent Runner 的调用线程中同步生成，触发阈值后会额外产生一次模型请求。摘要失败会降级为窗口记忆；后续可把摘要作为独立后台任务，并用摘要版本号和乐观锁处理并发更新。

## 面试话术

> 长对话不是无限拼接历史。我保留最近消息处理指代，把更早信息压缩成有字段约束的评审状态，并记录压缩游标避免重复计费。真正影响发布判断的状态还会写入业务表，不把事实只交给模型记忆。
