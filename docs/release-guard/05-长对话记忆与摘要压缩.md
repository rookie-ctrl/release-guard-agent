# Phase 5：长对话记忆与摘要压缩

## 记忆分层

- 最近消息窗口：每次调用只加载最近 `rag.agent.recent-message-limit` 条消息，默认 12 条。
- 结构化摘要：达到 `summary-trigger-count` 后，将窗口外消息压缩为服务名、版本、风险、发现、用户决策、已完成检查和待办事项。
- 单条长消息：超过 `max-message-chars` 时，先生成并缓存该条消息的有界摘要，原文仍保存在消息表中。
- 评审状态：结构化内容同步保存到 `ReleaseReview`，并通过 Session 的摘要游标标记已压缩到哪条消息。

## 实现过程

`ConversationMemoryService` 在构建模型上下文时先检查消息数。只取游标之后、最近窗口之前的消息，结合已有 JSON 状态调用模型摘要；摘要解析成功才推进游标，失败则记录警告并继续用最近消息，避免摘要异常阻断评审。

使用 `summaryThroughMessageId` 而不是每轮都摘要全部历史，可避免重复压缩和摘要成本随会话长度线性增长。Flyway V3 为游标增加字段。

## 单条长消息压缩

`buildMessages` 对最近消息和旧消息都检查单条长度。默认超过 `6000` 字符时，按每段最多 `6000` 字符分段，用“上一段摘要 + 当前原文片段”迭代生成摘要，每轮摘要上限 `2000` 字符。单条最多处理 8 段；更长的原文只处理首 4 段和末 4 段，摘要明确标注中间未检查的段数。摘要也提示模型不能据此声称完成逐行审查。

成功摘要写入 `AgentMessage.compressedContent`，供后续轮次和旧消息汇总复用；`content` 原文不变。Flyway V6 新增摘要列。模型输出为空、超过限制或请求失败时，不缓存无效摘要，改为仅提供有界的首尾片段，并明确标注省略部分未检查。

两个阈值可通过 `rag.agent.max-message-chars` 和 `rag.agent.compressed-message-max-chars` 调整。它们按字符计数，不等价于精确 Token 计数。

## 上下文组成

```text
固定安全规则 + 结构化评审状态 + 最近 12 条原文或单条压缩摘要 + 本轮工具定义
```

## 当前边界

摘要目前在 Agent Runner 的调用线程中同步生成。旧消息压缩会额外产生一次模型请求，单条超长消息最多产生 8 次请求；摘要失败分别降级为窗口记忆或带遗漏提示的有限片段。字符阈值只能近似控制上下文规模，摘要可能遗漏代码细节，需保留原文用于核对。后续可把摘要作为独立后台任务，并用摘要版本号和乐观锁处理并发更新。

## 面试话术

> 长对话不是无限拼接历史。我保留最近消息处理指代，把更早信息压缩成有字段约束的评审状态，并记录压缩游标避免重复计费。真正影响发布判断的状态还会写入业务表，不把事实只交给模型记忆。
