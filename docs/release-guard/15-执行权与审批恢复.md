# 执行权与审批恢复

本次修改针对两个缺口：固定 120 秒锁短于 180 秒执行预算；外部审批成功、本地结果尚未提交时进程可能中断。

## 锁与执行权

`AgentRunLock` 用 Lua 比较当前锁令牌，只有当前持有者能续期或释放。锁 TTL 为 120 秒；`AgentRunLease` 在独立线程池中每 30 秒续期，不依赖模型线程或工具线程。续期返回 0、Redis 异常、数据库执行权不匹配或达到截止时间，都会撤销当前工作者提交资格。

`t_agent_run` 新增 `execution_token`、`execution_lease_until`、`execution_deadline_at`。取得 Redis 锁后，还必须在短事务中取得数据库执行权；未到期的数据库租约可阻止 Redis 异常切换后的第二个工作者。续期不能复活过期的数据库租约。

模型调用前后、工具实际开始执行前及最终结果保存前检查执行权。Run 状态通过 `WHERE id = ? AND execution_token = ? AND execution_lease_until > ? AND execution_deadline_at > ?` 条件更新，更新失败直接退出。关联步骤、会话状态和最终消息在同一事务写入，避免旧工作者遗留结果。普通异常也要经过这一校验，不能把接管者改成 FAILED。工具审计记录另有乐观锁版本，防止并发覆盖。

模型调用在独立有界线程池执行，消费者只等待剩余预算；超时后即停止等待及提交。取消 Future 无法保证已经发出的 HTTP 请求被外部终止，但晚到结果无法写回 Run。恢复接管保留原截止时间；人工确认后的下一执行阶段重新计时。

`AgentRunRecovery` 每 30 秒扫描：租约过期但未超预算的 Run 经 Outbox 重调度；达到截止时间的 Run 标记 FAILED；长时间停留在 CREATED 的 Run 重投递，修复消息被旧锁挡住、随后确认掉的窗口。

## 审批操作

`AgentConfirmationService.decide()` 的事务只验证批准并持久化操作，不调用外部接口。Run 在外部结果确认前保持 WAITING_CONFIRMATION。

`t_approval_operation` 的 UUID 是 operationId，同一次批准仅允许一个操作（confirmation_id 唯一）。规范化原始参数在调用前保存，外部键始终为 `releaseguard:approval:<operationId>`，接管和重试都不换键。写工具不能从普通 ToolExecutionService 或模型路径绕过持久化操作直接执行。

| 状态 | 行为 |
| --- | --- |
| PENDING | 批准及参数已提交，等待后台处理 |
| EXECUTING | 短事务领取，具有独立尝试令牌及 60 秒租约；外部调用等待上限为 15 秒 |
| SUCCESS | 已确认审批单，保存外部 ID 和结果 |
| UNCERTAIN | 超时、断连、结果缺失或本地提交异常，不能确认失败 |
| FAILED | 外部通过 ApprovalRejectedException 明确拒绝，包括幂等键参数冲突 |

后台每秒扫描到期操作，在有界执行器中运行。恢复先按原键查询外部结果，查到即完成本地记录。只有网关明确声明 `supportsApprovalIdempotency()` 时，未知结果才允许使用原键重新请求。未声明时保持 UNCERTAIN，继续查询或人工核对，查询为空不能证明第一次请求失败。

成功落库、工具审计、Confirmation EXECUTED、工具观察、Run CREATED 与恢复 Outbox 在同一个短事务提交。事务回滚时整个本地结果回滚，操作仍能重新对账。尝试令牌阻止旧审批工作者覆盖接管者结果。对账使用退避，最长间隔 300 秒。

## 外部幂等契约与演示存储

DevOpsGateway 创建审批必须接收幂等键，并可按键查询。真实实现声明支持幂等前，须保证唯一约束、相同键相同参数返回原单、相同键不同参数拒绝、业务创建与幂等记录在同一事务提交，且幂等记录保留时间覆盖重试和恢复周期。

MockDevOpsGateway 的记录保存在 `t_mock_release_approval`，用唯一幂等键持久化参数指纹、审批单和结果。创建采用 REQUIRES_NEW 模拟外部系统独立提交，因此本地结果事务回滚不会删除已经创建的单据。审批编号改为 `REL-<UUID>`，不会随应用重启重置计数。JSON 对象字段顺序变化不会被当作参数变化。

Mock 使用同一个数据库中的独立事务模拟外部持久化；真实系统必须自行兑现该协议。对于覆盖或更新类外部写操作，若需要拒绝旧执行世代，还须增加对方校验的递增 fencing token，本次创建审批接口未提供此类更新操作。

## 迁移与验证

新增 Flyway V8。包含 Run 执行权字段及索引、工具审计版本列、审批操作表和 Mock 外部记录表。应用启动时正常迁移。部署时先停止旧版本消费者，再迁移并启动新版本，避免旧代码继续使用无令牌条件的保存路径。历史外部成功但本地记录丢失的审批没有可追溯的原操作键，需人工核对；新协议不能补造旧键。

运行 `mvn test`。新增测试验证续期跨过原 TTL、截止后停止续期、续期失败撤权、旧令牌无法保存 FAILED/最终消息、条件更新及相关写入共同回滚、外部成功后本地回滚恢复同一审批单、并发相同键只有一条业务记录、参数变化拒绝、审批接管后旧尝试不能覆盖、查询优先恢复、不支持幂等时不盲目重试、本地提交异常保持 UNCERTAIN、恢复不重置预算及超时终止。

数据库集成测试使用 H2；续期时序使用可控时钟。尚未执行真实 Redis/MySQL 多进程故障注入、180 秒真实长任务压测，或真实外部审批服务的契约验证。

可描述为：任务允许重复调度，通过执行权校验保护本地状态，通过外部幂等和对账避免重复业务副作用。保证范围取决于外部幂等契约及记录保留时间，不宣称端到端 Exactly Once。

参考：[Redis 分布式锁](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)；[AWS 幂等重试设计](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)。
