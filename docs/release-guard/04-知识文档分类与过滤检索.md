# Phase 4：知识文档分类与过滤检索

## 设计原因

原 RAG 将所有文档放进同一个索引，通用问答场景可以接受，但发布评审需要区分发布规范、事故复盘和操作手册，也要避免把其他服务的故障经验误用于当前服务。

## 实现

- `DocumentEntity` 新增 `documentType` 与 `serviceName`。
- 上传接口允许传入文档类型和服务标签，未提供类型的旧文档归为 `GENERAL`。
- 解析入库时将标签写入每个 ES Chunk。
- ES 新索引将标签映射为 `keyword`；既有索引通过 `putMapping` 补字段。
- BM25 与 kNN 两路查询都使用同一组类型/服务过滤条件，再按原逻辑做 RRF 融合。
- Agent 的 `searchKnowledge` 要求指定文档类型，可选指定服务名，并返回原文、文件名、分块号和相似度。
- Flyway V2 为已有 `t_document` 增加元数据列。

## 演示资料

`docs/demo/` 提供发布规范和订单服务字段删除事故复盘。上传时分别选 `RELEASE_POLICY` 和 `INCIDENT`，服务标签填写 `order-service`。Agent 可以先找适用规则，再找相似事故作为风险证据。

## 面试话术

> RAG 不只做向量相似度。发布评审有明确的业务域，因此我把类型与服务作为结构化 metadata，在 BM25 和 kNN 召回阶段同时过滤，避免先全库召回再在应用层过滤造成候选集被无关文档挤占。
