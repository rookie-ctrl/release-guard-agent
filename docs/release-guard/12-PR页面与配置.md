# 步骤 4：PR 页面与配置

## 操作步骤

1. 上传公司规范，等待文档显示已入库。
2. 在页面上方粘贴公开 GitHub.com PR 链接，点击“开始 PR 评审”。
3. 后端创建固定提交会话，页面显示 PR 与 head SHA，并自动发送首个评审问题。
4. Agent 读取 GitHub 工具与知识库，SSE 展示执行和结论；继续提问沿用当前 PR。
5. PR 更新后重新点击“开始 PR 评审”，创建新会话。

“演示发布”单独创建 order-service v2.3.7 的 Mock 会话。页面恢复会话时显示模式，工具历史不作为普通聊天文本展开。

## 配置与范围

公开 PR 可匿名调用，匿名限流时可以在本机 .env 配置 GITHUB_TOKEN，再通过 run-dev.cmd 重启。Token 只由后端持有，不传入网页或模型。

当前只支持公开 PR。后端检查 PR 目标与 head 仓库可见性；即使 Token 有私有仓库权限，也拒绝私有 PR。原因是当前应用未实现登录与访问控制，不能开放私有代码读取接口。

模型收到必要的 PR 描述、diff 和上下文。工具只读，不执行仓库代码。未提供 CI、覆盖率和生产数据时明确标为未知，不能据此推断全部测试通过。

GET /api/github/preview?url=<编码的PR链接> 可单独查看公开 PR 读取结果，不调用聊天模型。错误通过 error 返回中文信息，不回显 Token。

GitHub 限流时，页面显示中文原因和响应 Header 提供的预计恢复时间（北京时间），而不是笼统的工具失败。鉴权、权限和限流错误不自动重试。重启应用不会恢复 GitHub 配额；仅在本机配置 Token，不要把 Token 发到聊天或提交 Git。
