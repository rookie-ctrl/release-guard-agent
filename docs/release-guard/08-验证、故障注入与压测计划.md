# 验证、故障注入与压测计划

## 本阶段目标

验证工具执行边界与可重复执行语义，并明确哪些能力目前仅完成代码实现、尚未通过集成环境验证。测试结果以实际命令输出为准，不预设通过结论。

## 已加入的单元测试

`ToolExecutionServiceTest` 覆盖以下边界：

- 缺少必填参数和额外参数时拒绝执行，并断言工具未被调用。
- 高风险工具在缺少确认时拒绝执行，并断言工具未被调用。
- 禁止级工具始终拒绝执行。
- 同一 run、工具和参数的只读工具成功调用可重放保存结果，避免重复访问外部系统。

执行命令：

```bash
mvn test
```

## 后续故障注入

- Agent worker 在工具调用前、调用中、写回结果前被终止，检查 RUNNING 状态恢复策略和只读安全重试。
- RabbitMQ 重投同一 run，验证 Redis 锁、run 状态检查和消息确认行为。
- Redis 不可用时验证事件序号、互斥锁和 SSE 重连的降级边界。
- 外部审批系统超时或返回未知结果时，验证幂等键、人工核对路径和 Outbox 重试不会错误地重复高风险动作。
- SSE 客户端断线后携带 `Last-Event-ID` 重连，验证持久事件回放及过期游标提示。

## 后续集成与压力验证

- 使用独立 MySQL、Redis、RabbitMQ、Elasticsearch 和兼容模型服务执行完整会话、检索、确认及恢复流程。
- 分别测量会话并发、工具执行耗时、SSE 活跃连接、队列积压、Outbox 延迟及摘要压缩效果。
- 压测需记录环境规格、数据集规模、并发模型、持续时间、错误率和 p50/p95/p99；没有实测前不对吞吐量作承诺。

## 当前边界

本阶段的单元测试不替代真实依赖服务上的端到端验证。Mock DevOps Gateway 只用于演示 Agent 流程；生产使用前仍需实现具备身份鉴权、审计、下游幂等和超时语义的正式网关。
