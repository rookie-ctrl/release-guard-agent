# 步骤 2：PR 变更与代码上下文

## 已实现

GitHubGateway 读取真实 PR 元信息，创建包含仓库、head SHA、目标分支 SHA 和 merge base SHA 的快照。merge base 来自 GitHub Compare API，BASE 文件上下文与 PR 三点 diff 使用同一比较基线。

文件列表每页 20 条，返回 nextPage。每个文件包含 diffPage，用于定位对应单文件 patch，避免一次向模型发送整个仓库。GitHub 文件列表最多支持 3000 个文件，超过时明确标记 listingIncomplete。

Diff 和源文件内容每次最多 80 行、5000 字符，返回 nextStartLine、truncated 和 lineClipped。缺失 patch、API patch 行数不完整、二进制、非 UTF-8 或超过 128 KiB 的文件明确标记，不能解释成“没有风险”。

HEAD 内容从 PR 的 headRepository 读取，支持 fork；BASE 内容从目标仓库的 merge base SHA 读取。所有路径由本机编码，拒绝目录穿越。

## 提交一致性

读取实时 PR 文件列表前后都检查 head 和 base SHA。PR 更新时拒绝混用新旧 diff，提示创建新评审会话。文件上下文和 CI 都使用会话固定的 SHA。

## CI 语义

读取 Checks 和 Combined Commit Status，均分页；区分 FAILURE、PENDING、SUCCESS、PARTIAL、UNKNOWN。没有 CI、权限不足或只包含 skipped/neutral 时不会显示“测试通过”。CI 不提供覆盖率、生产监控和真实回滚能力证明。
