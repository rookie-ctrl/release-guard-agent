# Phase 2：统一工具执行框架

## 设计目标

模型输出只是一份不可信的工具调用请求。执行之前由 Java 侧检查注册白名单、JSON 对象结构、必填参数和额外字段，再按风险等级决定是否允许执行。

## 实现结构

- `AgentTool`：单个工具的执行入口。
- `ToolDefinition`：名称、描述、风险等级、超时、重试上限及 LangChain4j JSON Schema。
- `ToolRegistry`：启动时收集 Spring Bean，建立白名单；未注册的名字直接拒绝。
- `ToolExecutionService`：参数验证、幂等键、调用审计、超时执行和结果复用。
- `agentToolExecutor`：有界线程池隔离阻塞工具调用，避免占满公共 ForkJoinPool。
- `DevOpsGateway`：外部 DevOps 系统适配边界；当前由 `MockDevOpsGateway` 提供固定演示数据。

## 风险治理

只读工具由 Agent 自动调用。高风险工具 `createReleaseApproval` 只能生成待确认请求，常规执行器拒绝直接运行；用户确认后由单独的确认执行入口调用。`FORBIDDEN` 工具永久拒绝。

## 幂等与审计

幂等键由 `runId + toolName + arguments` 做 SHA-256。成功调用再次出现时复用已保存结果；同一幂等键处于运行中时拒绝重复执行。每次调用保留参数、结果、风险、状态和耗时。

## 当前边界

超时通过 `CompletableFuture` 限制调用方等待时间并取消任务；只读工具最多重试一次，高风险写工具不自动重试。若未来接入不响应线程中断的外部客户端，还需要在 HTTP/RPC 客户端自身设置连接与读取超时。

## 面试话术

> 模型只能提出工具调用，实际执行由 Java 白名单和 Tool Executor 控制。我在同一个入口做 Schema 校验、风险分级、超时与幂等审计，高风险写操作需要后端确认状态通过后才能执行。
